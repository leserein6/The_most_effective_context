# 已确认需求与采用的默认决策

## 目标和边界

建立完整 Project 管理体系与 workspace，不限于 MVP，不做软件页面。入口是现有 CodeBuddy CLI，长期状态为 Markdown，必要操作用脚本，Git 做版本与同步。总体机制独立于编排模式。

## 已明确确认

| 项目 | 规则 |
|---|---|
| 类型 | development、learning、one_off；one_off 为轻量、几轮交互可完成的一次性目标，不以是否跨会话为判据，需要持续演进的目标归 development/learning |
| 组织 | 状态 → 类型 → 具体 Project |
| active | 当前推进 |
| archived | 暂时不推进、尚未完成 |
| completed | 目标已达成 |
| 粒度 | 一个独立目标对应一个 Project，可以跨多轮 |
| 首要动作 | 每轮检查活跃 Index，其核心是各需求的一句话说明 |
| 归属不明 | 问创建新项目还是接续哪个项目，不能猜测 |
| 新建 | 整理名称、类型、一句话目标，用户确认后创建 |
| 决策冲突 | 先指出；明确修订按新要求执行，否则问清 |
| 状态变更 | 用户确认后变更；明确要求直接执行，不重复问 |
| 日志 | 归属真实 Project 的交互，每轮回复前写有意义的详细流水；归属未确认或用户批准无 Project 例外时不伪造 checkpoint |
| 压缩 | 容量阈值或阶段结束时判断；摘要用于恢复，原始流水归档保留 |

## 用户统一采纳的十二项建议

1. 自动选模式、简短告知、允许切换，用户指定优先。
2. 澄清、研究、规划、执行、审查、学习、编排七模式。
3. 编排时主 Agent 负责理解、拆分、协调、验收，不做具体子任务。
4. 可独立拆分且值得协调时自动使用多 Agent，简单任务直接做。
5. 明确任务直接执行；关键歧义或重大取舍才询问。
6. 每轮自动保存进度、决策、知识；未确认建议不记为确认。
7. 明确验收条件并提供证据，未验证项明示。
8. 公共规范/Prompt 先提炼候选，用户确认纳入；项目内经验自动记录。
9. 安全可重试失败自动处理，保留恢复位置，关键阻塞问用户。
10. 允许多会话；共享状态写入冲突检查，不静默覆盖。
11. 自动本地保存；Git commit/push 仅用户要求时执行。
12. 交付完整 workspace 包和验证脚本，用户在 Mac CodeBuddy 实测。

## 实现采用的可调整参数

Python 3.9+、macOS/Linux；日志阈值 32 KiB；单文件恢复输出上限 12000 字符；恢复为本地进程中断回滚。它们是工程选择，不冒充用户固定要求。

## 尚需真实环境验证

agent.md 是否按预期加载、七模式选择是否合理、Subagent 调用是否可用、每轮写回遵守率。没有本地模型会话，不能把这些列为已通过。

## 本轮入口澄清

每轮用户输入需显式锚定 Project、Task 与 Mode，首次回复第一行固定显示三者；新阶段不等于新Task。Task按预期交付临时路由到五类方法组，经对应二级索引按需读取当前协议。Task类别与Project类型/生命周期/Mode分离，不建立Task数据库。
