# 验收清单

自动脚本检查和真实 Agent 行为分开验收；通过前者不能推断后者已通过。

## 自动验收

运行 tests 和 demo，预期退出码均为 0。覆盖生命周期、三类型、确认门槛、并发旧 token、代码产物不使状态 token 失效、目标说明刷新 Index、操作重复、错误 payload 无部分写入、日志原文完整性、进程中断回滚、路径越界拒绝、执行权限保留、公共知识确认以及安装不覆盖。

## CodeBuddy 实测

| 场景 | 输入/操作 | 预期 |
|---|---|---|
| 归属不明 | 新会话说“帮我整理报告”，多个候选 | 先 Index，询问新建或接续，不猜 |
| 新建 | 提出新独立目标 | 先给名称/类型/一句话目标，确认才创建 |
| 同项目多轮 | 补充同一报告的要求 | 接续原 Project，不每轮新建 |
| 三类项目 | 开发、学习、一次性目标各一个 | 归入状态下相应类型 |
| 跨会话恢复 | 关闭再启动，说继续已有项目 | 读取进度、决定、问题、下一步，不整库加载 |
| 决策冲突 | 要求与原确认方案相矛盾的行为 | 先指出；未明确修订时询问 |
| 模式切换 | 从调研进入实现再审查 | 自动切换，读取相应协议，简短告知 |
| 编排 | 两个可独立子任务和后续审查 | 真正派发；主 Agent 协调/验收，不伪装工具输出 |
| 每轮记录 | 完成一轮后检查文件 | 当前进度与操作流水都有实际内容 |
| 用户确认状态 | 任务做完但未要求完成 | 仍 active；建议后用户确认才迁移 |
| 归档恢复 | 暂停后要求继续 | 归档未完成，确认恢复 active，历史保留 |
| 阶段压缩 | 标阶段结束/日志达阈值 | 评估摘要，归档完整原文，恢复摘要有来源 |
| 知识候选 | 发现可复用经验 | 项目内可记；公共纳入需确认 |
| 并发 | 两会话基于同 token 更新 | 一个成功，一个冲突，重读合并 |
| 外部失败 | 子任务工具失败 | 报告/安全重试，保留恢复点，不声明成功 |
| Git | 普通工作一轮 | 无自动 commit/push；明确要求才执行 |

建议保存前 10 轮真实记录，统计归属是否准确、是否重复询问、相关协议是否加载、是否每轮写回、验证是否真实。发现漏执行先修入口/协议与反馈，再考虑 Hook；不把未验证 Hook 放进默认配置。

## 交付的完成标准

完整架构与已确认需求可审阅；七模式与通用协议可读取；核心管理脚本可运行；测试/演示可重复；安装不覆盖已有文件；真实 CodeBuddy 未实测项明确标出。
