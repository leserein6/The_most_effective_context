# Project Resume — 恢复协议

**触发**：用户在新的或已有的 Session 中要求继续某个 Project。

## 流程

1. 根据明确名称/ID 定位对应的 `projects/<id>/project.yaml`；若存在多个可能对象，先澄清，不猜测。
2. **优先只读当前实例的最小状态**：`intent`、关键约束、`state.summary`、`state.next_action`、`state.blockers` 和引用索引。
3. 判断恢复所需的证据是否充分；仅当当前行动依赖历史设计、决策或代码时，再按引用打开对应文档/文件。
4. 对状态过期、路径缺失、交叉 Session 冲突或未验证完成项标明不确定性；必要时先核对实际产物。
5. 简要告诉用户：这是什么项目、目前可靠状态、下一步建议；然后按本轮 Task 和相关执行协议继续。

## 验收

- 不依赖旧 Session 的全部聊天记录，也能定位已确认意图和下一步。
- 不把项目摘要当成“所有结果已验证”；关键事实可回查来源。
- 没有找到项目文件时明确说明，不凭印象生成虚假恢复进度。
