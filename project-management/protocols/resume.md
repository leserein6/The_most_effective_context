# Project Resume · 跨 Session 恢复协议

**激活条件**：用户希望继续已创建的 Project，或要了解其可靠现状。

## 从轻到重读取

1. **定位项目**：使用用户提供的 ID/名称查找 `projects/<id>/project.yaml`；同名多个则先确定具体对象。文件不存在不能凭记忆假装已恢复。
2. **先读当前快照**：优先获取 `intent`、`constraints`、`state.phase`、`state.summary`、`state.next_action`、`blockers` 和引用索引；无需默认扫描全部聊天、日志或示例。
3. **按下一步的依赖补载**：需要解释设计理由才打开决策文件；需要续写代码才检查相关源码；需要证明完成才核对证据/测试。
4. **验证关键状态**：检查引用是否存在、完成声明是否有支持；对异常中断、可疑过期、并行 Session 更新或证据缺失明确标示不确定性。
5. **向用户说明恢复情况**：简单呈现“项目是什么 / 已知完成什么 / 仍有什么阻塞 / 下一步建议”，然后执行本轮 Task；如果要修改项目，转入 [Maintain](maintain.md)。

## 失败处理

- 无实例 → 报告未找到，不擅自创建项目。
- 摘要与实际产物冲突 → 以新核实事实为依据，必要时走 Maintain 修正快照。
- 日志太长 → 只用与本轮工作有关的部分，不为完整感一次性加载。

**恢复成功的标准**：从项目持久化快照及必要证据得出可信的当前状态，并能定位下一步；仅凭 AI 说“我还记得”不算恢复。
