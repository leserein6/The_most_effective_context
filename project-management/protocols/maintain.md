# Project Maintain — 维护协议

**触发**：已有 Project 的进展、需求、决策、约束或引用发生变化。

## 流程

1. 确定 Project 身份；读该实例的 `project.yaml`，必要时读取相关决策/证据文件，不预先加载全历史。
2. 将当前消息与已有数据对比，分类为：执行进展、普通任务、新建议、重大方向/范围/约束变更或仅讨论。
3. 仅为涉及字段加载 [字段维护契约](../schema/project.md)，必要时读取 [Few-shot](../examples/intent.md)。
4. **重大变更**：展示原内容 → 拟修改内容 → 影响，请用户确认后再写。普通子任务不应自动改写 `intent`。
5. **进度变更**：依据真实产物、验证结果更新 `state.summary`、`state.next_action`、阻塞及相关引用；没有实际进展不造进度。
6. 按需更新决策/日志资料，保留可追溯依据；执行后校验文件状态并向用户报告。

## 不变量

- 项目长期意图不因临时 Task 漂移。
- 原本有分歧或未验证的内容保持其状态，不得静默改写成事实。
- 不强制每轮创建 Task 文件，也不为每句聊天产生日志。
- 多处文件更新失败时明确哪些写入已成功，不能谎称事务原子性。
