# Project Create — 创建协议

**触发**：用户希望建立一个可持续维护的长期 Project。进入前仅需读 [Project Management README](../README.md)。

## 流程

1. **判断是否真的是 Project**：长期目标、需多轮持续推进或需跨 Session 恢复；单轮普通任务不自动创建 Project。
2. **提取已知信息**：问题、期望结果、范围、交付物、约束和验收方式；不把 AI 推断当成用户确认。
3. **判断清晰度**：如缺失信息足以影响项目定义，则按需加载 [Grill-me](../../harness/protocols/clarify.md)；每轮优先解决最关键的一处含糊。
4. **生成可审阅草案**：此时加载 [字段契约](../schema/project.md) 与 [模板](../templates/project.yaml)；当提取/修订方式不清楚时再读 [Few-shot](../examples/intent.md)。
5. **向用户展示草案并请求明确确认**：指出待定字段和关键假设。**用户说“帮我创建项目”不等于已确认 AI 生成的草案**。
6. **确认后才写入**：在 `projects/<id>/project.yaml` 创建项目实例，校验 ID 唯一性与文件存在/内容一致；仅需要时创建历史/证据文件。
7. **反馈事实**：说明创建的真实路径、已确认内容、未决问题、建议下一步；写入失败不得声称创建成功。

## 禁止

- 用户未确认最终草案就创建正式 Project。
- 为凑齐字段而凭空杜撰目标、范围或验收条件。
- 默认把本轮 Task 或完整聊天记录保存在 Project 中。

**交付条件**：可恢复的实际项目文件 + 用户知情确认的项目定义。
