# 操作流水与压缩

每轮用户交互结束前统一追加有意义的操作流水，包含关联的 WI-ID（如果有）、做了什么、改了什么、验证了什么、失败/阻塞与结果；不是只写成果摘要，也不记录私有思维过程。

触发判断为混合机制：current.md 达到 32 KiB 或本轮重要阶段结束（phase_end=true）。resume/checkpoint 返回 compression_due。32 KiB 是可调整的工程初始值，不是用户固定需求。

需要压缩时，主 Agent 提供待压缩 current.md 的实际路径、本次/下一阶段目标、有效定义/规格/决定位置。摘要生成者读完整待压缩原文，关键截断须补读。摘要只保留下一阶段继续工作需要的内容，使用以下四个标题：

| 必需标题 | 填写内容 |
|---|---|
| `## 已完成` | 实际产物、版本、已验证条件和证据路径；部分完成/未验证不能升级为完成 |
| `## 决策` | 有效决定及用户确认依据、替代关系；建议仍标建议 |
| `## 未解决` | 失败、阻塞、待核声明及已排除的有价值尝试 |
| `## 恢复位置` | 下一动作、必需输入/具体位置、对应协议；不复制凭据与隐私 |

已有规格、代码和决定全文只引用路径，不重复粘贴。主 Agent 检查摘要能否支持接续；不把推测升级成事实。摘要生成者只回传摘要，不修改共享日志或删除原文。此处同时规定摘要输入和输出，不另设一份压缩 Prompt。面向接续与引用已有产物参考来源 S03。

调用 compact，原文按字节归档到 logs/archive，追加带来源链接和 SHA256 的摘要，重置活跃流水。doctor 校验归档哈希。归档原文不删除。

脚本只检查摘要非空及四个标题，语义完整性由 Agent 复核。summary.md 仍会增长，恢复默认有截断标记；过长时按项目阶段阅读，不无限递归压缩或删原始摘要。
