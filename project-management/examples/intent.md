# Few-shot — Project Intent 的提取与维护

> 本文件只供 **intent 提取/更新判断** 使用，非项目真实数据；使用时以 [字段契约](../schema/project.md) 为准。

## 示例 A：需求模糊，应先 Grill-me

**用户**：「我想做一个 AI 知识管理工具。」

**错误**：立即确定技术栈、平台和十个功能，并创建 Project。

**正确**：先说出当前理解（希望开发一个 AI 知识管理工具），询问最关键问题：「你首先希望它解决哪种已有工具无法解决的知识管理问题？」确认方向后再形成可审阅草案。

## 示例 B：从具体需求提取 intent

**用户**：「我希望 Agent 能跨 Session 继续同一个长期项目，不用让我每次重复解释，先支持创建、更新和恢复；暂时不要多 Agent。」

**草案**：
```yaml
intent:
  problem: "新 Session 丢失长期项目上下文，需要用户重复解释"
  desired_outcome: "Agent 能依据持久化项目状态创建、维护、恢复长期工作"
  success_signals:
    - "新 Session 能定位项目现状和下一步，且不凭空推断进度"
scope:
  in: ["项目创建", "项目维护", "项目恢复"]
  out: ["多 Agent 编排"]
```
**动作**：向用户展示以上草案并请求确认；未确认不创建正式项目。

## 示例 C：普通功能任务不应改写 intent

**原 Project intent**：提供稳定的跨 Session 项目恢复。

**用户**：「给恢复流程加一个缓存。」

**正确**：作为功能/设计任务处理；除非用户明确改变总体定位，否则不更改 `intent`。

## 示例 D：重大定位变更需确认

**原范围**：仅支持特定 CLI。

**用户**：「之后我要支持所有常用 AI Agent，不再限定那个 CLI。」

**正确**：指出范围与交付影响，展示拟修改字段和差异，确认后才持久化更新。不得静默覆盖。
