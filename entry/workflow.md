# 按需参考：一轮任务怎样闭环

核心问题：**怎样保持本轮目标、所用方法、结果证据与项目记录一致？**

入口是 [agent.md](../agent.md)，它规定每轮锚定Task。当前Task及路由规则已在有效上下文时，不要求反复读本文件。

## 执行关系

1. 明确本轮Task的结果、对象与关键约束，首次回复简短显示；用户纠正则更新，不默认取消原目标。
2. 检查活跃Project Index，按已明确归属接续；信息不足先问，不能猜测或自行创建。
3. 依据主要交付进入 [一级索引](../agent.md)，再到选中的二级索引与当前协议。一级列Task类型，二级列场景分支，正文给具体思想方法。
4. 执行中仅遇新阶段/事实缺口/关键歧义才加载对应方法。用户指定某方法且范围清楚时可直达正文；不要为完成目录流程而无谓绕行。
5. 将完成声明与当前版本证据对应。失败、部分完成、未验证保留真实状态，不把若干局部通过自动相加为整体通过。
6. 回复前由主Agent按Project维护协议统一写进度与操作流水；写入冲突重读比较合并，不能只刷新token强行重试。

## 不混淆四个概念

| 概念 | 例子 | 存储/用途 |
|---|---|---|
| Project | 账单分页改造 | 跨会话长期目标 |
| Task | 本轮查清游标为什么重复 | 本轮主要结果，不独立持久化 |
| Task 类型 | answer/proposal/change/assess/learn | 临时路由，不写入mode字段 |
| Mode / Evidence | research、debug、verify等 | 当前工作方式/方法，按需切换 |

checkpoint仍只接受clarify/research/plan/execute/review/learn/orchestrate；design记plan，debug记execute，verify与压缩沿用当前主模式，独立验收记review。Task类型与工作项编号不变成新的持久实体。

## 何时停下来

关键用户决定缺失/原约束冲突：列明具体影响后询问；普通实现细节自行选择。外部副作用结果不明：先核实效果，不盲目重试。工具不可用或项目写入失败：说明未完成部分，不能模拟成功。

完成本轮不自动变更Project状态；状态变化、公用规范纳入和Git提交仍遵守用户确认规则。详细Project操作按需读取其独立README。
