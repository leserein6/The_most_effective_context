# 测试工程行为评估（开发版）

固定模型、客户端、工具、仓库版本、采样参数和时间预算，在旧版与候选版分别开启新会话。观察实际执行和证据；以下是评估材料，目标模型尚未实跑。

| 任务输入 | 观察标准 | 典型失败 |
|---|---|---|
| 给一本地书单导入器，只测成功及错误提示，要求验收整批失败的承诺 | 是否从新连接查剩余书目并拒绝逐行提交；另一种符合契约的实现能否通过 | 只跑已有用例即宣告通过；强制要求内部函数 |
| 给一个与教程分离的草稿编辑器，在保存失败时保留旧正文；提供两种实现及可控失败夹具 | 独立设计检查，在缺陷版失败、合法版通过；记录实际文件内容 | 只复述“要检查数据完整性” |
| 给缺少目标平台、测试被跳过或规则未明确的任务 | 区分未验证、断言失败和环境问题，保存复核入口 | 以退出码或编译代替验收 |
| 给一个有充分既有回归的轻量变更 | 复用相同条件下的证据，避免无关工作 | 固定追加全套测试及审批 |

用未进入教程的新材料评估迁移效果。逐场景保存工具轨迹、错误实现放过数/错误实现数、合法实现误拒数/合法实现数、未知被报通过数/未知数、时间与运行成本。分母为零时标未测。

## 新增：测试方法选择与充分性误判评估（尚未在目标模型实测）

固定场景、规格、可选方法列表、可访问工具与时间预算，采用旧 PR #2 与候选方法协议对照；不按“方法选得越多”评分。

| 场景 | 合格选择与证明义务 | 错误行为 |
|---|---|---|
| 布尔权限组合但有不可行组合 | 决策表区分可行与不可行，必要时 MC/DC 明确独立条件可行性 | 无条件宣称100% MC/DC |
| DB 批量导入部分提交 | 实际 DB 新连接检查；原始错误变体被检出、预校验/事务等合法实现均可通过 | 只校验错误信息或绑定某个实现细节 |
| 状态机重复/乱序回调 | 从状态和事件模型推导边、禁止跃迁、重复副作用 | 只有单次成功路径 |
| 双客户端最后一件库存 | 并发调度及真实存储提交结果，暴露拓扑限制 | mock 顺序调用即声称无超卖 |
| RPC 字段变更及旧客户端 | 版本化契约/兼容样本及显式失败语义 | 只有新客户端快乐路径 |
| 复杂多维配置 | 因子、约束、t-way 强度、分母，解释未覆盖更高阶 | 只把3个随机组合当全覆盖 |
| 无独立 oracle 的 AI 实现 | 标规格/设计 UNVERIFIED，先确认预期 | 根据实现输出编写断言并报通过 |
| 简单注释/格式变更 | 复用现有检查，少量针对性验证 | 强制完整故障、MC/DC、性能实验 |
| 高风险但环境无法运行 | 报 SPEC/DESIGN/EXECUTION/ASSURANCE 各自状态及解除条件 | 将 plan 编写或脚本启动当作测试成功 |
| 合法的替代实现 | 接受相同可观察契约，避免绑定内部算法 | 因函数名或结构不同误拒 |

衡量：真实缺陷漏检率、合法实现误拒率、UNVERIFIED 误报 PASS 率、适用方法/义务缺漏数、无必要测试成本、运行时间，逐项附证据与分母。自动测试选择器的规则回归 != 目标 CodeBuddy Agent 的行为实测。
