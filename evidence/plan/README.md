# Plan：让工作项可以直接执行

输入：本轮目标、已确认约束、设计/规格路径、相关代码位置。没有目标先澄清；没有实现事实先查；不能在计划里虚构函数或路径。

## 步骤

1. 把验收条件编号，逐项找到负责实现它的工作项；编号仅用于计划对照，不建立独立 Task 数据库。
2. 按可独立验收的产物拆分。把初始化/配置与使用它的功能放在同一工作项，避免“只建空目录”算完成。
3. 每项填齐：读哪些文件、改/建哪些文件、依赖项、输入输出、必须保持的行为、执行动作、验证方法、预计成功现象。
4. 涉及接口时写已决定的准确名称、字段、类型和错误语义；尚未决定的关键值先处理，禁止只写“合理处理边界”。
5. 为每项安排正常行为及有关风险的验证。命令先从仓库构建/测试配置中查，不猜 go test/pytest 等命令一定适用。
6. 检查依赖顺序、同名接口是否一致、是否漏验收条件、是否多做需求外功能。写相同文件或依赖未完成产物的项不得并行。

## 工作项格式

编号/产物；约束；读取/写入范围；前置依赖；输入→输出；动作1…N；检查命令或人工检查；预期与失败处理。

只需要数步的小修改可以短列上述必要信息；复杂计划存所属 Project 的 work/ 中，下一会话引用路径，不重复抄入 state。

## 出口

所有关键验收都有负责项且无阻塞 → 按既定方式 execute/orchestrate，不反复问继续。
有重大取舍 → 呈现具体选择；授权不含实现 → 只交付计划。
