# 后端工程风险清单（按需）

只检查与当前改动相关的部分；这不是要求每个任务实现整套基础设施。结论要落到代码/规格/测试，不能对业务凭常识补造规则。以下是本项目场景适配的审查问题，不声称是外部模板原文或行业合规标准。

| 变化范围 | 必须具体检查的行为 |
|---|---|
| 请求/接口 | 字段缺省与零值是否不同；谁校验；兼容旧调用方；错误码与错误信息是否保留 |
| 重复调用/交易 | 幂等键从哪来；相同键不同参数如何处理；查询+写入是否存在竞态；超时是未知结果还是明确失败 |
| 状态机 | 允许哪些旧态→新态；是否条件更新；重复/乱序事件会否重复改变资金；终态如何判定 |
| 数据库/事务 | 哪些数据必须原子；事务外副作用如何处理；锁/隔离/并发行为是否由实际实现支持 |
| 缓存/路由 | 命中、未命中、故障分别走哪条路径；降级是否读到不满足业务语义的数据；A/B或LDC差异是否保留 |
| Go 并发 | goroutine谁启动/结束；context取消是否传播；共享对象谁保护；并发限制是否覆盖真实在途请求；锁内是否阻塞调用 |
| RPC错误 | 传输错误与业务错误是否分开；包装后还能否识别；下游响应是否丢失；对外是否泄露内部信息 |
| 多源分页 | 排序键是否全序；同时间戳如何区分；游标边界是否重复/跳过；过滤后不足是否补齐；某源失败如何表示 |
| 补偿/重试 | 是否可重试、总次数/时限、退避；重试前如何核实已发生效果；失败是否有可恢复记录 |
| 资源/观测 | 文件/连接/协程是否释放；超时是否包含排队；日志/指标能否定位问题且不暴露敏感信息 |

没有规格支撑的业务选择先问或标待决定。例如不能从“银行调用超时”推断“允许解冻”，也不能用单机内存锁声称跨实例幂等成立。
