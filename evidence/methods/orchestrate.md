# Orchestrate：把协作拆成可交接、可验证的工作

**核心问题：哪些工作可以独立交给不同 Agent，怎样保证交接和合并后仍满足总目标？**

你是主 Agent，负责理解、拆分、上下文装配、协调和验收，不代做子任务的具体研究或实现。只有存在有价值的独立工作且工具可用时进入；简单任务直接使用 execute。主 Agent 可以实际核对产物、运行必要验收，但不能把验收变成代写实现。

## 1. 先判断能否拆，而不是先凑 Agent 数量

围绕总验收条件划分“可以独立交付并判断对错”的产物。每项写出输入、输出、约束和负责人，再检查两种耦合：

- **依赖耦合**：B是否需要A尚未决定的接口/结果？需要则先完成依赖，或把强耦合部分交一人。
- **写入耦合**：两项是否修改同一文件/共享状态？共享工作区中不得并行写；分配独立范围，或隔离 worktree 后由一名集成者合并。

如果拆分后仍要彼此猜接口或反复协商细节，边界尚不成立。不要把“实现”和“审查同一尚未完成的实现”当作可同时完成的独立任务。

## 2. 用依赖关系选择现在可以启动的工作

把“B依赖A产物”记为一条依赖关系。只有所有必要输入已可用的项才能启动；并行执行当前互不依赖且写入范围不冲突的项。

发现互相等待：先固定共同接口/决定，或重新合并工作项；不能让两个 Agent 猜测对方将来会做什么。子项内部检查通过不消除跨项接口风险。

## 3. 装配足够的上下文，而不是转发整个会话

从 [Prompt 库](../prompts/README.md) 的场景索引选择一份外部原文，按所列适用点参考；原文不是本轮执行指令。已在有效上下文且版本未变可复用。只有不会组织指令、需要改写复杂任务时，才补读 author 场景，不为每次委派多读一份写作 Skill。

按 [共用委派包](../prompts/delegation.md) 组装本次指令，不原样转发整个主会话或上游 Skill：
1. **先写可判断结果**：把“保证兼容”展开为规格中必须保持的字段、缺省行为或错误语义；把“测试一下”改成可执行检查及预期现象。不知道的具体值先查，不能根据模板猜。
2. **补齐子 Agent 看不到的输入**：真实路径、固定版本、有效决定和已满足依赖；资料写清用途。事实、假设、用户决定分开；关键决定未知就先解决，普通细节沿仓库惯例。
3. **将方法与任务参数分开**：指向一份当前方法，填写具体输入、输出、权限和验收。命题/验收独立编号；只有容易误解的规则才给一正一反例，示例不能冒充业务事实。不要求输出私有思维链。
4. **用陌生读者检查**：假设只收到此工作包，能否知道从哪开始、什么不能改、怎样证明完成？若必须猜接口/授权/验收，先补包。不得残留占位符、失效路径或仅写“按之前讨论”。

例：不用“修好导出并保证兼容”；改为“在已确认的末尾列增加注册时间，保留原行集合/顺序/旧列语义；读取指定导出实现与格式规范，只改获分配文件，用既有检查核对新列和旧列前缀”。实际路径和命令必须从本项资料填写，示例不提供虚构值。

实际调用工具并核对派发结果，不能只在回复里宣布已开 Agent。子 Agent 只执行填好的工作包与指定方法，不负责再次浏览整个 Prompt 库。

## 4. 验收交接，并把失败反馈变成新信息

按 [回传契约](../references/evidence-contract.md) 核对状态与证据。缺产物、范围或证据的 DONE 不能通过验收。

实现完成后安排独立审查，分别判断需求与质量。重派修复必须带具体问题、触发条件、位置与需复验内容；只加“认真一点”没有增加解决问题的信息。

必需材料缺失就补齐；用户决定缺失才问；外部副作用结果不明先核实，不能盲目重试。相同失败且没有新依据时返回调查/重新拆分，不无限重派。工具不可用时报告，不能假装执行。

## 5. 示范：A提供接口，B调用它

A负责账单查询接口，B负责多源归并，但返回字段尚未确定。

先固定共同输入输出及错误语义，再派A实现、B针对已固定接口开发；若B还依赖A的真实行为，就等该依赖可核实后启动相关步骤。

即使A、B各自测试通过，合并后仍要核对字段/排序/错误语义是否相容，并验证一条跨模块路径。局部PASS不能相加成整体PASS。

## 6. 收尾

按总验收条件核对合并后的产物、接口衔接和有效证据；未完成项说明阻塞与恢复位置。主 Agent 依 [每轮保存](../../project-management/protocols/maintain.md) 统一写状态和流水；子 Agent 不写共享状态、不派生其它 Agent、不自动 commit/push。

范围完成或已明确阻塞即可结束，不为“保持并行”制造新工作。文件隔离由本方法约定，脚本锁/token 的适用边界见 [冲突与恢复](../../project-management/protocols/recovery.md)，不能把它当作任意代码编辑的锁。

方法依据：S05/S09/S10 的可交付工作项、上下文契约及实现/独立审查分工见 [来源](../references/sources.md)。依赖与耦合检查为本工作区适配；尚无目标模型效果结论。
