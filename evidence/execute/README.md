# Evidence: Execute（实际执行）

**Use when**：任务要求真实修改文件、代码、配置或外部系统；可产生可检查的产物。  
**Don't use when**：只是评审方案、查证事实，或用户尚未授权对应修改。

## 执行闭环

1. **确认当前交付和授权边界**：目标对象、改动范围、完成条件是什么；对不明对象或破坏性行为先查清。
2. **先读取真实现状**：只加载受影响文件和依赖，不假定目录、权限或历史状态。
3. **按最小切片实施**：已有明确计划则按计划；计划存在矛盾先注明并处理。代码类任务优先使用对应环境的测试策略；不强制把非代码任务套进 TDD。
4. **每步核对结果**：比较实际产物与预期。异常行为或测试失败，先进入 [Debug](../debug/README.md) 定位原因，不连续猜测式打补丁。
5. **完成前验证**：进入 [Verify](../verify/README.md)，根据实际工具输出、测试和文件内容检查能够作出哪些完成声明。
6. **回复可审计结果**：写明真实位置、哪些已验证、哪些未完成、是否产生外部副作用。提交成功不代表功能测试通过。

## 失败处理

工具不可用、无权限或写入失败时明确停止相关动作，报告已经成功的部分；不能用计划或生成文本冒充真实操作。

## V1 工作模式补充

目标边界清楚时直接推进，关键歧义或重大取舍才询问。编排模式主 Agent 只协调验收。并发代码修改按文件所有权或 worktree 隔离；结束前由主 Agent 调用 checkpoint 保存进度和流水。
