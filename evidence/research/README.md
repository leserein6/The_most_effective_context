# Evidence: Research（查证）

**Use when**：用户需要来源支撑的事实、技术机制、版本差异或代码仓库调查。  
**Don't use when**：用户只要创意或假设性设计，无须核实外部事实。

## 执行方法

1. **将问题缩成可查证命题**：记录目标事实及版本、时效、适用条件。只查与命题有关的信息。
2. **选最接近事实的材料**：框架机制优先对应版本源码/规范；仓库问题优先当前仓库文件；时效信息优先有日期的一手材料。优先直接阅读而非仅凭搜索摘要。
3. **沿证据链定位**：识别文件、符号、链接、版本或页码；检查来源**确实支持**结论，必要时交叉验证。
4. **区分事实与推断**：来源冲突时说明冲突和时间口径；无法查到时标注未知，不补造引用。
5. **先给结论，再给最小依据**：交代关键限制；避免把不相关的检索过程倾倒进回复。

## 退出条件

结论有可定位依据；或已明确说明无法核实及原因。引用不真实、版本不符、把假设当结论，均不能视为完成查证。

**场景**：用户要求“核查 tRPC-Go 某版本的超时传播”，应检查该版本具体调用链；仅解释 RPC 超时通识不够。
