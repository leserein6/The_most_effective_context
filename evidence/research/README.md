# Research：用可定位事实回答当前问题

适用：事实查证、源码机制、版本差异、选型依据。输入至少有要回答的问题和适用范围；用户只需假设性构思时不强制检索。

## 步骤

1. 将问题拆为少量可核实命题。例如“tRPC-Go 超时怎么传递”要进一步识别实际版本、调用位置和配置来源。
2. 先检查项目已有资料是否直接回答；涉及当前实现读源码，涉及规范读规范，时效问题查当前一手材料。
3. 做源码调查时按入口 → 调用者 → 关键函数 → 配置/数据读写 → 返回处理追踪；找到符号后读上下文，不能只凭文件名或搜索命中下结论。
4. 对每个命题记录：结论、文件/函数或 URL、版本/日期、直接支持点、无法验证处。摘要或代码注释不能替代与结论相关的实现检查。
5. 来源冲突时比较版本、适用范围和实际代码；仍不清楚就保留两个事实及冲突，不强行选一个。
6. 回答对当前 Project 的作用：用于哪个决定、采用条件、怎么验证。资料索引登记来源，项目结论写 notes，不把整篇材料灌入当前状态。

## 分支与停止

找不到准确版本：先查依赖清单/锁文件；仍找不到，说明目前只能回答哪个版本，不暗示就是用户环境。
访问被阻：记录未能读取的来源；不能引用搜索摘要冒充全文核实。
任务只是窄问题：只追该调用链；用户要全仓理解时再采用范围化的代码库调查，不生成无关全套文档。

## 输出

结论｜observed/cited/inferred/unverified｜来源定位与版本｜对项目的作用。
附最关键的限制；不在最终回复倾倒检索流水。完成条件是命题有足够直接依据或明确无法查证的边界。
