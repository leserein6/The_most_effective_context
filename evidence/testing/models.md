# 高价值测试技术：从模型构造用例的最低操作协议

本页用于在选择到特定方法后按需深入，不是默认全量加载或要求每个项目完成所有模型。

## 1. 决策表与 MC/DC（DT / MCDC）

输入是**已确认的布尔判定表达式**，不是从代码抄出的未确认业务规则。

- 决策表：列出每个业务条件的有效值、不可行组合、期望动作与原因。先覆盖语义规则，再考虑缩减。
- MC/DC（修正条件/判定覆盖）：对判定中的每个原子条件，找一对有效输入，使该条件改变、整体判定结果也改变，其它独立条件保持相同（unique-cause 版本）；条件耦合/不可行时需要专门说明所用变体和限制。
- 例：允许导出 = 有权限 A AND 账户有效 B。测试 (A,B)=(T,T)→允许、(F,T)→拒绝、(T,F)→拒绝，分别显示 A、B 对判定有独立影响。三例不证明其它业务条件、数据竞争或整体正确。
- 对有短路、副作用与共享条件的实现，检查条件求值可观察性，不能仅通过三行真值表宣称已达到工具测得的 MC/DC。
- 适用于高风险复杂判定及适用标准要求；一般服务端业务不默认强制 MC/DC。

## 2. 状态机 / 模型驱动（ST / MBT）

从规格画出 状态集合 S、事件 E、转移关系 T、守卫 G、状态不变量 I、终态与可恢复行为。
- 先检查所有**允许**的边和关键守卫；再给每个禁止边至少一个负例；
- 对重试、重复事件、乱序、故障恢复设计短事件序列；验证副作用的次数和持久状态，而不仅是返回状态码；
- 可将事件序列生成接入模型驱动测试，但模型版本必须与需求同步；
- 记录已覆盖状态数/可达状态数、已覆盖边数/可达边数，**序列覆盖另算**，单边覆盖不保证多步行为。

例：任务 INIT→RUNNING→DONE；取消后 CANCELLED 为终态。检查 RUNNING→CANCELLED 是否可行、CANCELLED 收到 DONE 回调是否错误恢复 DONE、重复完成是否增加副作用。

## 3. 性质与蜕变测试（PROP / MET）

从不可违反的规律出发，而不是从已有实现生成期望值：
- 性质：例如序列排序后元素多重集合不变、结果有序、重复排序不改变结果；生成器需覆盖空集、重复键、极端长度与非合法输入策略；
- 记录 seed、采样域、参数约束、收缩后最小反例；测试次数是采样量，不是全域覆盖率；
- 蜕变关系：例如在满足前提时给输入整体平移常量，排序后的相对顺序应不变。先验证关系对需求确实成立；
- 差分测试只在参考实现足够独立、输入语义对齐且比较规则明确时使用。多数实现同结果不自动证明正确。

## 4. 变异测试（MUT）

定义从真实失效模式推导的变异算子：比较符边界变换、删除校验、遗漏回滚、交换状态守卫、抑制异常传播等。
1. 固定测试集与候选实现，选择代表性变异（可用工具自动化）。
2. 执行：真正错误的变异应引发断言失败；若测试仍通过，该变异可能揭露测试盲点。
3. 把编译失败、不可执行、疑似等价与有效变异分开，审查分母。
4. 增加或改进测试后再执行；同时确认合法实现未被不必要地拒绝。

变异杀伤率只说明测试对**选定变异算子集合**的判别力，不等于真实缺陷发现率。

## 5. 组合测试（CMB）

确定因子、语义等价取值、约束和交互强度 t。用覆盖数组生成 t-way 可行组合；记录输入模型与组合覆盖报告。2-way 适合优先探索常见双因子交互，**不是保证错误只涉及两因子**；高风险相关因子可以局部提高强度。参考 NIST ACTS。

## 6. 并发、存储、故障注入（CON / DB / FI）

先写出禁止发生的状态与可观察证据（例如两个成功请求不能共同扣减同一份库存）：
- CON：明确竞争方、屏障/注入窗口、交错、提交/冲突结果；跨实例承诺必须有实际跨实例环境或等价且经论证的模型；
- DB：使用真实存储引擎与目标隔离级别，事务提交或回滚后从独立连接读取；本地 mock 不能证明持久化；
- FI：明确注入位置（调用前、请求发出后、响应前、提交前/后）、超时/重试边界、外部副作用与恢复观察；记录每次故障行为和注入生效证据；
- 高风险还要做故障模式分析（如 FMEA）和恢复策略检查。所有实验必须隔离生产数据与真实外部副作用。

## 7. AI 编码下的 oracle 与独立复核

- 在编码前固定需求来源、关键性质与预期结果，避免实现驱动测试“自圆其说”；
- 对复杂规格可由独立审查者/Agent 复核，但应提供不同的证据基础、反例与理由；不能把“不同提示词”当独立真值；
- 验证双向性：错误实现应失败、不同合法实现应通过；
- AI 生成测试可以是候选，但必须接受人工或独立模型对规格、覆盖分母与 oracle 的审查。
