# 测试方法目录（按问题选择，不按工具选择）

本目录是 Development Task 的可复用方法知识库。每种方法都必须回答：**何时使用、由什么模型推导测试、覆盖对象及分母、判定依据、可能漏掉什么**。同一需求可组合多种方法。测试层级（单元/组件/集成/系统/端到端）与设计技术（边界值/状态迁移/MC/DC 等）是两个正交维度，不能互相替代。

## A. 规格驱动 / 黑盒

| ID | 方法 | 适用触发条件 | 产生的覆盖义务与局限 |
|---|---|---|---|
| EP | 等价类划分 | 输入域可分成有效/无效类 | 每个有依据的类至少有代表；分区错了会漏测 |
| BVA | 边界值 | 长度、数值、时间、索引、配额 | 每个边界两侧/边界值；不覆盖多条件交互 |
| DT | 决策表 | 多条件组合决定动作/拒绝原因 | 枚举有效规则、动作、不可达项；不证明并发行为 |
| ST | 状态迁移 | 订单、审批、交易、任务生命周期 | 合法/非法边、状态不变量、关键事件顺序；单路径不代表交错 |
| SC | 场景/用例链 | 业务流程及参与者交互 | 成功、失败、撤销与补偿；仅端到端样例不足以覆盖分支 |
| CT | 契约测试 | RPC/HTTP/消息生产者-消费者 | 字段、缺省、错误语义、兼容矩阵；不证明下游内部行为 |
| MBT | 模型驱动测试 | 状态复杂、规则可枚举 | 从状态图/决策模型生成路径，记录模型版本；模型本身必须审查 |
| CMB | 组合测试（t-way） | 配置、环境、参数相互影响 | 给出因子、取值、约束、交互强度 t 与组合覆盖；不代表全组合 |
| MET | 蜕变测试 | 单次输出难以确定 | 给出输入变换与输出关系；关系本身要从规格验证 |
| DIFF | 差分测试 | 有独立且可信的参考实现/协议实现 | 比较同输入的可观察等价；两个实现也可能共同错误 |

## B. 代码/性质驱动

| ID | 方法 | 适用触发条件 | 产生的覆盖义务与局限 |
|---|---|---|---|
| PROP | 性质测试 / Property-based | 不变量和代数性质可形式化 | 给定生成器域、性质、种子、收缩和反例；随机样本非全称证明 |
| FUZZ | 模糊测试 | 解析器、协议、非可信输入、边界 | 种子、语料、时长、崩溃分类与复现；不保证业务语义正确 |
| BR | 语句/分支覆盖 | 关键实现路径尚无证据 | 执行过的语句和分支比例；覆盖不等于断言有判别力 |
| MCDC | 修正条件/判定覆盖 | 高风险、多个布尔条件决定关键行为 | 逐原子条件证明其独立影响判定；有耦合条件时记录限制 |
| MUT | 变异测试 | 想验证测试集能否发现典型错误 | 检出/存活/等价变体及有效分母；变体集不覆盖全部缺陷 |
| SA | 静态分析/形式分析 | 类型、数据流、资源、安全或关键不变量 | 规则、范围、告警与人工判定；需区分证明与启发式检查 |
| REV | 人工/独立设计审查 | 不清楚需求、oracle 或高影响变更 | 审查模型、假设、失效模式、证据；不以审查意见冒充执行结果 |

## C. 运行环境与非功能属性

| ID | 方法 | 适用触发条件 | 产生的覆盖义务与局限 |
|---|---|---|---|
| DB | 真实存储集成 | 事务、隔离级别、持久化、迁移 | 提交/回滚后重新连接观察、隔离组合、约束与恢复 |
| CON | 并发/线性化检查 | 竞态、幂等、限流、分布式竞争 | 指定交错/并发负载、唯一性与最终效果；单机模拟不得宣称跨机 |
| FI | 故障注入 | 超时、断连、依赖错误、重试与补偿 | 故障点、注入窗口、恢复界限与观测，保留原始失败 |
| SEC | 威胁建模与安全测试 | 鉴权、信任边界、敏感信息、输入污染 | 威胁/权限矩阵、负向用例、扫描与手工复核 |
| PERF | 性能/容量/稳定性 | 吞吐、延迟、资源、扩缩容 | 指定环境、分布、峰值、SLO、置信范围及持续时间 |
| REL | 恢复/容灾/部署验证 | 断电、重启、重放、回滚、灰度 | 故障假设、恢复目标、数据不变量、实际运行环境 |
| ACC | 无障碍/可用性评估 | 产品有明确可访问性或操作性承诺 | 基于使用场景和标准的人工/自动结合检查，不能仅靠脚本 |

## D. 防止「层级」与「方法」混淆

选择方法之后，再选择最小可信执行层级：

- 纯函数/格式转换 → 单元或性质测试；
- DB/事务语义 → 真实数据库集成测试（模拟数据库不足以证明提交/隔离语义）；
- 上下游 API → 契约测试 + 必要的集成测试；
- 跨实例/故障/重试 → 与拓扑相符的系统/故障测试；
- 用户业务完整链路 → 少量端到端验收。

必要时在同一验收条件下组合不同层级，记录每层能够证明的范围。默认不要求全方法、全层级、全覆盖。

**详细操作与例子：** [方法选择](selection.md)、[模型和深度技术](models.md)、[充分性审查](adequacy.md)。
