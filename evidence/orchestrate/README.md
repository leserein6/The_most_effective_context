# Orchestrate：主 Agent 负责分工和验收

进入条件：存在可独立验收的工作项，委派收益超过协调成本且有实际 Subagent 工具。主 Agent 理解、拆分、协调、验收，不代做具体研究/实现。简单任务使用 execute。

## 主 Agent 顺序

1. 明确本轮目标、规格来源和验收条件；有关键歧义先澄清。
2. 列工作项，写各自的输入输出和依赖。只有依赖已满足的项可以启动；读同一份资料可以并行，改同一个文件不能并行。
3. 给每项指定唯一执行者和写入范围。强耦合改动合并交一人；独立 worktree 的结果由单一集成者整合。
4. 读 [委派模板](../prompts/delegation.md)，填写实际约束与位置。实现用 [implementer](../prompts/implementer.md)，审查用 [review](../prompts/review.md)。不得只派“把后端做完”。
5. 子 Agent 只获得完成职责所需的上下文；不要假设它看到主会话。派发后核实工具返回，不虚构 Agent 已启动。
6. 收到报告时先核对 DONE/PARTIAL/BLOCKED/FAILED。产物位置、关键差异和证据齐全才送审；无证据的 DONE 退回补齐。
7. 独立审查需求符合与实现质量；不通过只发回具体问题，修复后只复查变化及受影响范围。
8. 全部局部产物合并后核对跨项接口和整体验收，不能把若干局部 PASS 直接相加成系统 PASS。主 Agent 统一保存项目状态与流水。

## 失败分支

缺必需上下文 → 补给子 Agent；关键用户决定缺失 → 问用户。
工具不存在 → 报告并提出切 execute，不声称已执行。
同项连续两次失败且无新证据 → 暂停该项重新规划/澄清，不无限重派。
后续项依赖未完成 → 等待，不以猜测接口抢跑。

子 Agent 不派新子 Agent、不写共享 Project 状态、不自行提交；具体边界见 [协作协议](../protocols/delegation.md)。

参考 S05、S09、S10：明确任务交接、实现和独立审查。调度/回写/重试上限为本体系适配。详见 [来源](../SOURCES.md)。
