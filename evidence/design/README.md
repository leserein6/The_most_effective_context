# Evidence: Design（方案设计）

**Use when**：主要输出是用户可审阅的架构、规格、技术路线、方案取舍。  
**Don't use when**：只是在实施已确认的小修改，或仅要求查一个事实。

## 设计流程

1. **问题优先**：区分用户动机、预期效果、当前限制与 AI 的假设；明确本轮设计的边界。
2. **只解决真正的分歧**：有实质取舍才比较可行方案，指出代价与风险；无真实分歧时只给最简设计，不强造备选。
3. **由上到下展开**：先系统职责和交互边界，再展开数据模型、流程和失败路径；避免一开始罗列类名或目录。
4. **保持决策清晰**：区分 `confirmed / proposed / unresolved`；与用户已有决定冲突时必须说明，不能静默覆盖。
5. **可实施的交接**：针对已确定设计，写出足以执行的最小分步计划；每一步包含可检查的目标或验收方式，不替执行者写整套实现代码。
6. **退出**：用户能识别设计解决了什么、做了哪些取舍、哪些仍待定。设计完成不等于已交付。

若关键需求影响设计，先按需进入 [Clarify](../clarify/README.md)；用户要求落地时再进入 [Execute](../execute/README.md)。
