# 路由与失败示例

例子是判断方法，不是本轮用户需求或授权。

| 输入与已知事实 | 正确路径 | 禁止的误判 |
|---|---|---|
| “已有 CSV 导出，加一列”，格式在项目里 | 查代码 → execute → verify | 重问整套产品定位/格式 |
| “我想做个学习助手”，目标未定 | clarify 集中问关键分歧 | 自定移动端/RAG后直接实现 |
| “超时后偶尔重复扣款” | debug 取观测、定位 → execute → verify | 看到超时就无条件重试 |
| “查这个版本 RPC 错误为何丢失” | research 定位版本、调用/返回链 | 只给 RPC 通识 |
| “帮我设计资金冻结状态机” | design 明确不变量/转换/失败 → plan | 只画节点不给并发和补偿语义 |
| “审查这批改动是否实现分页要求” | review 固定差异，分别查需求/质量 | 测试绿就断言全部符合 |
| “并行做 A、B”，B 需要 A 尚未确定的接口 | 先完成接口或串行，再编排 | 两个执行者各猜接口 |
| “继续 Go 学习”，前置没讲过 | learn 恢复进度，先补必要规则 | 把懂 C++当懂 Go语言规则 |

若一个请求同时有几个阶段，按实际顺序切换。模式选择不创建新 Project，不以流程标签代替产物。
