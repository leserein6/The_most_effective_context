# Subagent 协作

只有可独立分工且收益大于协调成本时自动采用。选择编排模式后，主 Agent 不做具体子任务，负责理解、拆分、派发、协调、验收。普通 execute 可以直接完成简单任务。

拆分维度：独立模块、独立证据来源、实现与独立审查。不要为了并行把强耦合修改分给多人。依赖显式列出：下游等待上游有效交付。

每份委派都用 prompts/delegation.md 的契约，指定负责的文件或独立 worktree；各子 Agent 的写入范围不得重叠。单一集成者合并变更。

共享 project.md/state.md/decisions.md/日志/Index 只由主 Agent通过 pm.py 写。Subagent 仅返回结果/操作/证据/阻塞/建议，不擅自更新已确认决策、项目状态或公共规范。

失败时判断可安全重试、改派或询问；禁止无界重试、隐瞒失败、重新运行会重复外部副作用的动作。完成后核查产物与证据，必要时交独立 reviewer。

并行文件写入不是 pm.py 能解决的问题；其 flock 只协调脚本调用。直接修改共享 Markdown 或同一代码文件绕过保护，必须避免。Git 跨机器同步不靠本地锁，见 recovery.md。
