# 委派与文件边界

派发前填委派模板；必需字段缺失时不要发送不完整任务。主 Agent 是唯一共享状态写入者，worker/reviewer 不能修改 project.md、state.md、decisions.md、Index、项目日志或公共规范。

| 子任务关系 | 安排 |
|---|---|
| 独立研究、各有输出文件 | 可并行 |
| 不同模块，接口已经明确 | 可并行；先给相同接口约定 |
| 改相同文件，或共享尚未明确接口 | 串行或合并一个执行者 |
| 审查依赖具体实现 | 实现产物固定后再审查 |
| worktree 独立修改 | 单一集成者合并，再跑整体验收 |

flock/token 仅管理 pm.py 的共享状态更新，不保护任意代码编辑。子 Agent 没有自己的持久 Task 数据库；需要的 brief/report 作为所属 Project 的 work 产物保存。

worker 默认不派生其他 Agent、不自动 commit/push。独立 reviewer 不修改工作区，不替实现者写自证结论。需要更多职责由主 Agent 明确派发，不让角色在执行中无限扩张。

失败由主 Agent核对副作用与原因后安全重试。新结果没有新证据时不要只加“认真一点”重新派发。具体错误、补充材料和需复查范围必须写进重派说明。

参考 S09/S10 的职责边界；项目共享状态/并发规则为本地约束。见 [来源](../SOURCES.md)。
