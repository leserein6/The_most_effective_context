# 证据分类与回传契约

observed = 实际工具/运行观察；cited = 来源直接支持；inferred = 有前提的推断；unverified = 尚未验证。
每条需写明具体声明、证据位置、对应版本/时间及覆盖范围。命令启动不等于成功，文件存在不等于内容正确，引用不等于行为已实测。

## 报告状态

| 状态 | 使用条件 | 必须附带 |
|---|---|---|
| DONE | 分派范围已完成且约定检查通过 | 产物、验证与限制 |
| PARTIAL | 有部分成果，仍有未完成/未验证 | 已完成与缺口分别列明 |
| BLOCKED | 必需输入、权限、环境或关键决定缺失 | 缺什么、由谁提供、恢复位置 |
| FAILED | 实际尝试失败，未达到条件 | 失败操作、观测结果、已发生效果 |

代码审查用 PASS/FAIL/UNVERIFIED 分别描述需求与质量；报告状态与审查结论不要混用。
不要求输出模型私有思维过程，只需要可审计的事实、选择依据、操作和证据。

完成前执行 [Verify](../verify/README.md)。结构化回传不证明内容真实，主 Agent 仍需验收。
