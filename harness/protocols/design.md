# Design / 设计协议

**适用**：需求分析、架构、产品方案、技术选型等“先形成方案”的任务。

## 执行方法

1. 明确问题、期望结果、已知约束与尚未确认的假设。
2. 先给高层边界和关键职责，再按必要程度展开结构与数据流。
3. 对真正影响决策的备选方案，比较收益、成本、风险和适用前提；不为了完整而列举无关选项。
4. 区分 **已确认决策**、**建议方案** 和 **待确认问题**；重大取舍不得默认为用户已同意。
5. 给出可验证的最小下一步和验收标准；设计完成不等于实现完成。

## 按需关联

- 核心需求不明确 → 加载 [Clarify](clarify.md)。
- 用户要求把设计写入长期 Project → 另走 [Project Management](../../project-management/README.md) 的维护流程。
