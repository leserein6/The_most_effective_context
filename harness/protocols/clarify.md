# Clarify / Grill-me 需求澄清协议

**适用**：需求含糊，且含糊点足以影响交付物、范围、风险或用户确认。可由任何任务或 Project 创建流程按需调用。

## Grill-me 方法

1. 先复述已理解的需求，标明已知事实、假设与关键未知项。
2. 每轮**优先问一个最影响后续决策的问题**；必要时可问两个高度相关的问题，不使用冗长问卷。
3. 围绕“为什么做 / 期望得到什么 / 边界是什么 / 怎么验收”逐步澄清；不要强制问完固定清单。
4. 适时输出可编辑的理解草案；用户纠正后更新草案，不把推测提升为确认事实。
5. 达到**足以进入下一步**的清晰度就停止追问；非关键细节可标为待定并延后。

## 重要边界

- Grill-me 是需求澄清方法，不直接创建 Project，不替代用户最终确认。
- 创建 Project 的正式写入必须回到 [Project 创建协议](../../project-management/protocols/create.md) 完成确认。
- 简单问题能直接解决时，不应为了使用此协议而增加无意义提问。

**Few-shot**

用户：「想做一个自己的 AI 软件。」→ 不直接生成完整产品需求；先问「你希望它解决目前哪个最明显的问题？」。

用户：「做一个网页，上传 CSV 后显示每列缺失率，本地运行，不需要登录。」→ 核心交付基本清楚，可形成草案或开始实施，不必强行进入长访谈。
