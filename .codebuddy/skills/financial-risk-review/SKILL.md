# 金融/资金后端风险专项 Review

**来源：** 用户历史 `financial-system-review.md` 的通用化改编；只把风险机制带入当前 Harness 的独立 Review，不照搬未经核实的旧业务规则。适用语言不限 Go。

## 核心不变量从哪里来

从本次经确认的业务规格、账户/账务契约、已核实的数据模型抽取，不自行发明余额可负、收支顺序、清算时限、具体监管要求。

针对实际发生的资金/状态变更，优先审查：
- **不多**：重试、并发是否可能重复扣/入账、重复发放外部效果。
- **不少**：失败/超时/消息丢失是否会遗漏业务承诺的动作，能否补偿。
- **不错**：金额单位/符号/精度/舍入/溢出，账户/币种和业务主键映射。
- **不乱**：合法状态跃迁、守卫条件、终态与幂等状态转移是否受控。
- **可追**：事实源、流水/交易单、审计标识、原始错误和 Trace 关联。
- **可补**：部分成功、提交结果未知、重启恢复、消息重放的确定处理。

## 沿单笔业务检查事实与状态

1. **状态机**：基于规格列合法状态、事件、守卫与不变量；查实际条件更新/CAS、version、affected rows，不假定读后再写天然原子。
2. **数据权威**：区分事实源、派生表、缓存、索引；核对改写/回查路径。不要默认“哪个库就是事实源”，以系统约定为准。
3. **事务边界**：DB、RPC、MQ、缓存、外部渠道各由谁提交，谁不在同一原子范围。关注 Commit 结果未知、回滚路径和补偿恢复。
4. **请求唯一与幂等**：唯一键范围/生命周期、重复请求与不同请求的碰撞、先查再写的竞态；外部副作用是否在保护范围之内。
5. **并发与余额**：扣减条件、并发交错、锁对象/粒度/释放，流水是否可能重复/缺失；自增流水 ID 不天然等于业务唯一键。
6. **金额**：核对精度和业务单位；避免二进制浮点直接承担精确货币计算，检查实际选定的整数/定点/Decimal 约定与范围。
7. **不确定外部结果**：RPC timeout、响应丢失、MQ 重投、外部渠道未知状态，明确查询、幂等重放和补偿机制；“超时 = 失败”不是安全推断。
8. **恢复与观测**：异常后谁发现未完成状态、何时重试/报警、日志能否重建单笔操作；不泄露敏感信息。

## 判断与输出

对每项问题提供**真实路径 + 输入/事件时序 + 破坏的不变量 + 可验证后果 + 证据**；优先给一个能区分正确/错误实现的反例。对发现不了事实源、未获权威规格或跨服务源码不可见的情况明确 `UNVERIFIED`；不要把检查列表逐项写成假缺陷。相关测试方法选择交给现有 `test-planner` / `evidence/testing/selection.md`，不是本 Skill 另起一套测试体系。
