# 向上汇报 SOP

## 目标
让接收方在最短时间知道「结果如何、风险是什么、需要决定什么」，而不是阅读工作流水。

## 输入与核实
确定汇报对象、时间范围、所需形式（消息/口头/周报）；从真实 Project state、Work Item、PR、工单和验收材料提取事实。区分已完成且验证、仅提交/待验收、进行中、待反馈、阻塞。比例只有定义清晰分母时可算；否则不用“完成80%”。

## 工作流程
1. **结果先行**：一句话说明本期可验证成果和总体状态。
2. **剩余与时间**：列尚未完成的关键步骤、当前依赖、下一检查点；引用已有链接或文件。
3. **风险预警**：标明已知事实、可能影响、触发条件和当前补救，避免等截止日才说。
4. **方案和建议**：存在真实权衡时给方案 A/B，比较质量/工期/风险并推荐；没有必要不凑两个方案。
5. **向上请求**：明确需要谁决定哪件事、何时需要回复；没有则省略。
6. **延期专用**：如有原承诺，列原日期、新预测及依据、已采取动作和需要批准的调整；新预测不是已批准承诺。

## 默认交付
**结论**：完成了……，当前……。
**已验证成果**：最多三项。
**下一步**：关键剩余与依赖。
**风险/建议**：仅在确有风险时。
**需您确认**：具体决策问题。

口头版 30 秒保留结果/风险/请求；周报版按项目展开。不得捏造进度、把测试通过等同于上线，或未发送却声称已汇报。用户要求发送仍需可用工具与明确授权。
