# 日常工作 SOP

## 目标
从实际工作项中找出今天最值得推进的三件事，防止待反馈和阻塞项遗漏；不是建立另一套 Task 系统。

## 数据规则
仅以已确认的 Project/WI 和用户提供的真实任务记录为准。Turn Task 是当前对话交互，不当作持久 Work Item。四栏看板是派生视图，不单独维护一套可冲突的任务状态。未知截止时间/负责人标未知，不猜。

## 执行流程
1. 读取活跃工作项及依赖，提取已知截止时间、负责人、业务影响、验证方式和最新进度。
2. 综合截止时间、是否阻塞别人、关键路径、风险和预计投入，选择 **今日 Top 3**，每项写下一动作与完成信号；若工作量超标，指出取舍。
3. 输出四栏：**待办 / 进行中 / 待反馈 / 已完成**。待反馈项特别标记「等谁、等什么、已等多久、何时会影响关键路径」。
4. 临期、事故、外部阻塞消息应及时处理；其他消息可由用户分批处理。不会擅自发送消息、设置日历或修改外部任务状态。
5. 用户要求日终复盘时，对比 Top 3 和可验证成果，说明未完成原因和明日第一步；不自动触发「下班交接」。

## 默认输出
Top 3（理由｜下一动作｜完成信号） → 四栏当前视图 → 最重要的待反馈/风险。
若用户仅要今日重点，就不额外输出整张看板。

## 校验
不把“提交代码/开过会”自动标为完成；真实验收依据优先。不把排序建议当成已获批准的业务优先级变更。Project/WI 写回只通过既有管理流程。
