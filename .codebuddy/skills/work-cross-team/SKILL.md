# 跨部门沟通 SOP

## 目标
让协作方一次理解「背景、需要做什么、交付格式和时间」，避免空泛催促；对方尚未答复不能当作已有承诺。

## 信息准备
查当前 Project 的目标、依赖 Work Item、既有对接记录和相关接口资料。确定真实的对接负责人、谁能批准、为什么要这个结果、影响哪个里程碑。找不到负责人则写「待确认」，不凭猜测 @ 其他人。避免分享与请求无关的敏感上下文。

## 执行步骤
1. **初次请求**：一句话背景 → 具体动作或资料（必要时给字段/格式/模板）→ 已知的最晚时间 → 时间依据和对方可能需要的前置材料。
2. **沟通卡点**：对方反馈不清楚时，分别确认是否缺权限、信息、环境、资源或决策；给出可行替代方式。
3. **跟催**：先确认困难，再提醒待交付的确切内容、此前约定时间（若有）以及下游影响；不使用无事实的紧急措辞。
4. **升级**：仅在真实关键路径受阻时，向有权负责人陈述影响、历次沟通、方案 A/B 和需要做的决定。推荐方案要说明成本及风险。
5. **闭环**：获得明确确认后，才把对方承诺、交付格式、时间及来源记录回 Project/WI；尚未确认的内容单独标注。

## 默认输出
**沟通目标**：需要对方采取的下一步。
**可发送消息**：背景｜请求｜格式｜最晚时间（如已知）｜需要确认的问题。
**无法按期时**：备选方案与升级条件。
**待记录**：哪些信息已经被对方确认。

## 边界
草稿不等于已发送；未经授权不发送、不修改对方工作项、不承诺别人资源。提案与已定方案严格区分。
