# 工作出错 SOP

## 首要目标
先阻止影响扩大，再如实通报、评估、经授权补救，最后建立可核实的防复发动作。不能为写好复盘耽误应急响应。

## 严重性判断
区分一般差错（文档、未发布代码、沟通）与高风险事件（生产事故、资金或数据不一致、误删、越权、隐私泄露）。高风险时立即提醒联系值班/负责人并遵守企业既有事故响应、权限和审批流程；本 Skill 不替代事故指挥。

## 执行顺序
1. **控制影响**：停止继续做可能放大问题的操作；不擅自生产回滚、修改数据库、批量重试、资金补偿、权限操作。这些动作必须经过明确授权和适当审批。
2. **事实快照**：记录发生时间、操作/版本、受影响系统或对象、现象、已经证实的影响、尚不清楚的影响、日志或变更证据。每条标注「证实/推测/待核实」，绝不捏造用户数量与根因。
3. **及时通报**：先给负责人发短报草稿，包含事实、已知/未知影响、已采取措施、需要支援或授权、下一检查点（若真实约定）。不隐瞒、不推锅，也不在未知时宣称恢复。
4. **补救方案**：列可行措施及其风险、审批、回退条件、验证方法。真正操作前先按权限与流程执行。
5. **验证恢复**：检查业务不变量、关键数据、外部影响和监控；命令执行成功不等于业务已恢复。
6. **复盘改进**：建立时间线，区分触发点、技术/流程促成条件和证据不足的假设；列出可以验收的改善工作项、负责人和已确认的期限。避免只有「以后更仔细」这类无效措施。

## 分阶段输出
**首次紧急短报**：事实｜影响范围（未知项明示）｜止损｜需要审批/支援。
**补救方案**：选项｜副作用｜授权条件｜验证与回退。
**事后复盘**：时间线｜根因证据等级｜整改 Work Item｜验证依据。

## 边界与验收
信息不充分时不编造。未经用户授权且不具备工具权限时，不发送外部消息、不动生产、不修改资金/业务数据、不宣称事故结束。已有 Project/WI 是唯一权威工作记录，不再建立独立行动项数据库。
