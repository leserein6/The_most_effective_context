# Go 语言专项审查（按风险加载）

**来源：** 用户历史 `go-code-review-skill.md` 的经核查改编，提炼到当前 Harness；非原文逐字复制。全局两轴审查和证据分级只由 `evidence/methods/review.md` 负责，此处仅补 Go 独有的错误机理。找不到该文档时，仍遵循“规格/实现质量分开、每项 finding 有真实路径和反例”的原则。

## 使用前提

- 已固定要审查的 Go 代码范围及版本（包括用户未提交改动）；先看相关入口、`go.mod` / Go 版本及真正触达的代码，不全仓扫描。
- 已有业务需求/接口契约则沿真实调用链检验，先从输入、状态和副作用构造反例；无规格时只能判断实现质量，不能声称需求符合。
- 普通样式问题不盖过正确性、并发与数据完整性；不是 checklist 每项都要报一个问题。

## 触发相应检查的故障机理

| 代码特征 | 检查的具体错误路径 |
|---|---|
| 返回 error、错误封装/转换 | 丢失错误、错误码/可重试语义被覆盖；错误链 `errors.Is/As` 的调用方是否仍可识别 |
| nil/interface、map/slice、方法接收器 | typed-nil interface、nil map 写入、共享底层存储、值复制导致的状态偏差 |
| `goroutine`、`channel`、`sync`、`atomic` | 谁启动/停止协程，取消路径是否可达；共享状态谁保护；锁范围、竞态、死锁、阻塞和资源泄漏 |
| `context`、timer、deadline | 创建和取消责任、下游 deadline/元数据传递；检查真实请求链，不把合理的 `context.Background()` 误报为错误 |
| DB/RPC/文件、连接/流 | 谁创建、关闭、复用；关闭发生在哪些正常/失败路径；提交/回滚异常是否遗失 |
| 编解码、输入/输出、溢出 | 空值、边界、超长输入、权限与数据泄露；只检查实际暴露面 |
| 性能敏感路径 | 按真实规模寻找无界分配、循环 RPC、N+1、热点锁等；没有数据不直接断言性能退化 |

## 证据与结论

1. 每个发现必须有 `文件/函数/代码位置 → 可达触发输入或交错 → 错误后果 → 对应规格/语言规则`；可独立检查时给最小复现或可运行验证建议。
2. 判断“已经被其它层保护”的可能性：唯一约束、外层锁、框架 Filter、defer、已有输入校验等，先查后报告。
3. 区分 **确定缺陷** 与 **有价值但尚未核实的风险**；明确需要什么证据才能升级结论。
4. 输出紧凑、按实际影响排序，不重复通用 Review 方法的完整模板。Go 专项不存在问题时直说“本次范围内未发现”，不宣称全局无缺陷。

若审查路径是 tRPC-Go/RPC，额外按需加载 [tRPC-Go 专项](../trpc-go-review/SKILL.md)；如涉及资金/账务，则按需加载 [资金系统专项](../financial-risk-review/SKILL.md)。二者不要求默认同时加载。
