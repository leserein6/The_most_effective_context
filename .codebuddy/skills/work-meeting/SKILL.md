# 开会 SOP

## 触发分支
用户说「准备会议」执行会前部分；说「整理纪要/会议记录」执行会后部分。不要强制用户走完整流程，也不假设可访问会议录音。

## 会前：会议是为决定什么
1. 从 Project/WI、设计文档和历史决策中明确会议问题、备选方案、待决策项及参会者需要的最少背景。
2. 为每个议题写：**要决定什么｜可选方案｜需要谁拍板｜依据资料｜预期产出**。
3. 如需会前材料，列真实文件路径或链接；未知参会者/会议时间标「待确认」，不自发邀请或发送。

## 会中/会后：从实际记录提取
1. 使用用户提供的笔记、转录文本或已授权资料，明确来源及时间。无法取得的会议内容不可臆造。
2. 区分 **讨论 / 建议 / 确认的决策 / 未决问题 / 行动项**。有人建议不等于团队已经批准；争议未解决保留不同意见。
3. 每个行动项写**具体动作、唯一责任人、截止时间、依赖、完成信号**；未知负责人填「待指派」，未知日期填「未约定」，不默认由主持人负责。
4. 会议纪要是草稿，待会议负责人确认后才能宣称正式决议。需要更新 Project/WI 时，复用已有数据和写入权限规则，避免重复建立任务。

## 默认输出
**会议主题与决策目标**。
**关键结论**（决策和建议分开）。
**行动项**：任务｜负责人｜期限｜依赖｜验收。
**待确认/分歧**。
**资料来源**：用户提供的记录、文件或真实链接。

## 结束条件与安全
决策、责任人、时间均有证据或明确标未知；不自动发送纪要、不安排日程、不虚构参会信息。用户只需议程就不生成会议纪要。
